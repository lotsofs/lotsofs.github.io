# The games module

Imported by `CLAUDE.md`.

Added 2026-11-12: an account system with an Age of Empires scenario timeline behind it, the first of what the owner means to track game by game (GAM), and since 2026-11-14 a page of Sims 2 checklists.

- **Its own accounts, copied from hideandseek** (the owner's choice: separate games accounts, not music's). It has its own `sessionScope('games')`, so being signed in to music or hideandseek says nothing here, and a test pins that. It also has its own `games.sqlite` / `games_test.sqlite`, `schema_migrations`, catalogue and stylesheet. The account files (`auth.php`, `db.php`, `migrate.php`, `inviteCode.php`, `rateLimit.php`, `ajaxGuard.php`, and the login, register, logout, language and accounts routes and views) are hideandseek's with the prefix changed. That makes them a third set of near-copies, and mtasa's, copied from these, a fourth (SHR): a bug fixed in one copy needs checking in the others. The ajax helpers keep music's names (`ajaxInt`, `ajaxText`, …; conventions trap 13).
- **Everything else is `games`-prefixed**: functions (`gamesAccount`, `gamesIsAdmin`, `requireGamesAccount`, `requireGamesAccountJson`, `runGamesMigrations`, `gamesAoe2Load`), constants (`GAMES_INVITE_CODE_*`, `GAMES_AOE2_*`) and CSS classes (`.gamesLayout`, `.gamesNav`, …), apart from the timeline's own `.aoe*` classes.
- **Everything is locked.** Unlike hideandseek's landing page, `/games` itself needs a login. Only `/games/login` and `/games/register` work signed out, and logging out lands on the login page. Invites are made on the accounts page, as in hideandseek, and the first account to register is the admin.
- **Not there until a feature needs it:** no hue, blind rating or toasts, and no favicon of its own, so it wears the site's `/favicon.ico`.
- **English only.** `config.php` offers `en`. The language route and menu were copied anyway, and the menu hides itself while there is one locale, so another language is a line in `config.php` plus a `lang/<code>.php` and its part files. `tests/cases/strings.php` and `tests/i18n-coverage.php` are hardcoded to music, so nothing checks this catalogue.
- **One fixed dark theme**, music's look: hideandseek's shell (sidebar on a desktop, bottom bar under 700px) with its palette on `:root` in `public/modules/games/css/styles.css`, using music's blue (`hsl(240, …)`) as the accent.
- **`001_create.sql` shipped on 2026-11-18 and is frozen**: a schema change is a new `002`, and a deploy ships at most one new migration, music's rule. An edit to a shipped file is a silent no-op on every database that has run it. `data/games_test.sqlite` has no live copy to reseed from: it holds the owner's own account and ticks, so before `001` shipped a new table was created in it by running the table's statements once (`aoe2_entry`, 2026-11-13), which leaves it matching `001` as written; its `youtube` column was added the same way, with `ALTER TABLE` (2026-11-14), so in that file it comes after `updated_at`, which no query minds since every one names its columns. It declares no `REFERENCES`, by the site rule.
- **Tests:** `tests/cases/games.php`, with its own `games*` helpers against `games_test.sqlite`. It stands alone (`php tests/run.php games`). Its accounts are not dropped between case files, since `dropAccountsAfter()` only knows music's database.

## Age of Empires (`/games/aoe2`)

- **The data is Julix's spreadsheet, read live**: the Individual Scenarios tab of "Age of Empires 1/2/3/4 Campaigns and Scenarios in Chronological Order", public, which Google serves as CSV at `GAMES_AOE2_SOURCE` with no key. Nothing about the scenarios is stored here, so the owner never updates anything when the sheet changes. All of it is in `app/modules/games/aoe2.php`.
- **The colours are the sheet's own** (the owner's wish, 2026-11-12): the rows wear them, and the lanes brighten them (below). The CSV has none, so they come from a second page: Google's HTML view of the same tab, `GAMES_AOE2_STYLED_SOURCE`, also public with no key (1.2 MB, scanned in 5 ms). There every cell is a `<td class="sN">` and a `.sN{…background-color:#rrggbb…}` rule colours it. A campaign fills its whole row with one colour, except the Game and Pack cells, which are coloured by game, so `gamesAoe2Colours()` takes the **Scenario** cell's. It reads game, campaign and scenario out of the same row, and keys the colour exactly as a tick is keyed, which matched all 547 scenarios (2026-11-12). So the two pages never have to agree on row numbers, and a colour map from an earlier fetch stays right for every scenario it names. Cells are placed by their `colspan`; a campaign's first cell is `class="s7 softmerge"`, of which the first class is the style. Every merge in the tab is in the title row, the full-width notes or the legend to the right, so none of them shift the scenario columns, and no `rowspan` is handled. The sheet uses 29 colours for 98 campaigns, so lanes side by side can share one, and four AoE III campaigns change colour act by act. The darkest colour, `#6489e6`, still has 6.3:1 contrast against the black page.
- **`gamesAoe2Load()` keeps a copy**, `data/games_aoe2_scenarios.csv` plus its colours in `games_aoe2_scenarios.csv.colours.json` (both gitignored), and serves it while it is under 10 minutes old. Older, it fetches the sheet (curl, 8 s, the system CA store added as `tools/import-buurten.php` does) and replaces the copy only with text that parses. A failed fetch serves the old copy marked stale, which the page says, and is not retried for a minute, or every page would wait 8 s on an unreachable Google. `clearstatcache()` comes first because both ages are read off file times. With no copy and no sheet the page says it has nothing. Each successful CSV refresh also fetches the HTML; when that fails or yields no colours, the last colour map stays. The colours never make the page stale and never hold it up beyond their own fetch. Whether the host can reach Google at all is unchecked on the host (GMS).
- **`gamesAoe2Parse()` finds the columns by their headers** (`Scenario Number`, `Scenario`, `Year`, `Civilization`, `Campaign`, `Game`, `Pack`), so a column the author adds does not shift the fields; a sheet without them parses to null and never replaces the copy. A row with no scenario name is skipped, which drops the blank rows and the notes. The number column says more than a number: `Ascent of Egypt   1` starts a campaign, `<End>   5` ends one, and a standalone scenario has a label with no digits. Years are free text (`c.8000 BCE`, `406 to 455`, `-`) and are only ever shown, never parsed: the order is the sheet's own. The export drops the sheet's hover notes and its wiki links.
- **A tick is keyed by `game|campaign|scenario`**, unique on every row (the game is what tells the AoE II and AoE IV Agincourts apart). Ticks are rows in `aoe2_check`, written by `/games/ajax/aoe2-check`, which refuses a key the current sheet does not have. **A scenario the author renames loses its tick on the page**: the row stays, under the old key, and shows again if the name comes back.
- **Each scenario has four columns the account fills in: Descriptor, Rating, Note and YouTube** (the owner's wish, 2026-11-13 and 14), after Pack, the Note taking the rest of the row. The list is about 1,024px wide in a 1280px window, so the columns are held to small minimums and 0.8em apart: at 1.2em and the first minimums, seven scenario names in the default view went onto two lines, and none do now (2026-11-14). With every game shown, the long AoE IV names still wrap. **A descriptor or note is cut off with an ellipsis like music's notes** (the owner's wish), on one line with its line breaks as spaces (a descriptor at 14em, a note at its column), and **its whole text, line breaks and all, is its hover box**: `data-tooltip` on the button. They are one row per scenario in `aoe2_entry`, keyed as a tick is (so a renamed scenario loses them the same way), written a field at a time by `/games/ajax/aoe2-entry` (`{key, field, value}`), and the row goes when all four are empty. The fields and their byte limits are `GAMES_AOE2_ENTRY_FIELDS`, and the SQL column is only ever a key of it. **A rating is a number from 0 to 10 with at most two decimals**, a comma reading as the point (`gamesAoe2EntryValue()`), shown without trailing zeros (`gamesAoe2EntryText()`) and in no colour, by the owner's choice. **Click to edit** (the owner's choice over always-open boxes): a cell is a `.aoeField` holding a button with the text, which `aoe2.js` hides behind a box while editing, saved on Enter or on leaving it and abandoned on Escape; a descriptor or note is a textarea, where Shift+Enter is a line break, as in music's note editor, and a line break is stored as `\n`; a refusal puts the old text back and says why. A box inside the button would be invalid HTML, and Firefox will not focus one there. The cell is `z-index: 2`, above the layer that makes the whole row tick it, so a click on a cell edits and a click anywhere else on the row still ticks. An empty cell shows a faint box on hover, or always where there is no hover. The button's `aria-label` names the column and scenario and carries the value, since a label replaces a button's content. A ticked row's fields turn blue and bold with the rest of its text. **A YouTube link is a ▶ that opens the video in a new tab, beside a ✎ that edits it** (`.aoeFieldLink`, then the button, whose `data-value` holds the link the editor starts from; an empty cell is the button alone). It is read like music's (`gamesAoe2YoutubeLinkIn()`, a copy of `youtubeLinkIn()` that also takes shorts and live links and a `v=` that is not first, and holds a bare id to a real id's 11 characters, so a stray word is refused), stored as music stores one, the id and `&t=` with the start in seconds, and shown as the watch link `GAMES_AOE2_YOUTUBE_PREFIX` builds from that. The editor is taller than the row, so opening and closing it lays the to-scale timeline out again, around the row being edited. On a phone they wrap under the details, Descriptor, Rating and YouTube side by side and the Note last (`order: 1`), on a line of its own; there `.aoeText` takes `min-width: 0`, or a long note on its one line held the page 1,088px wider than the screen. Checked in Chrome at 1280 and 390 px (2026-11-13): headings within a pixel of their cells, a click on a cell never ticks, a 300-character note with a line break stays one row high on a desktop, cut off, with both lines in its hover box, and the to-scale layout stays exact.
- **The hover box is `public/modules/games/js/tooltip.js`**, loaded with a `#gamesTooltip` box by the foot partial on every games page: put `data-tooltip` on anything, including what is added after load, since it listens delegated. A copy of music's cut to that one attribute, music's being a copy of ss2's: the modules share no scripts. Opening an editor hides it, since the button under the cursor goes away with no mouseout.
- **Filters are definitions, built for more** (the owner expects to add some). `gamesAoe2Filters()` lists each one: the field it reads, its options taken from the sheet (so a game code the sheet adds is offered at once, under its own name until `GAMES_AOE2_GAME_LABELS` names it) and its default. There are two, and a scenario must pass both. **The game**, defaulting to AoE II alone. **The DLC** (2026-11-12), the sheet's Pack column: since its codes repeat across games (`-` is every game's base game, `DE` is in three), an option is game and pack together, `packKey` (`II|TC`). **The defaults** (the owner's choice, 2026-11-13) are AoE II with its DLC up to The Last Khans (`GAMES_AOE2_DEFAULT_UP_TO`, in the legend's release order; all of AoE II's should the sheet drop it), plus every DLC holding a scenario the account has ticked, with its game, so the route reads the ticks before it builds the filters. A game off by default keeps its DLC ticked, since the DLC only count beside their game: a link naming that game, or its own box, shows all of it. On the live sheet a fresh account sees 161 scenarios, and one ticked Return of Rome scenario adds that game. The names come live from the sheet's legend, right of the data under "Game / Expansion Pack Legend", read by `gamesAoe2PackNames()`: in that column a row with nothing to its right heads a game (`GAMES_AOE2_GAME_NAMES` maps the heading to its code) and a row with a name is a pack of it. The cell is matched by ending in "legend", so the campaign "The Legend of El Dorado" is never taken for it. The label drops the year the legend gives, and the title keeps it; a pack the legend lacks shows its code. **A downloadable scenario is a DLC of its own** (the owner's choice): any scenario whose campaign starts "Downloadable Scenario" (Ayn Jalut, 2026-11-12) gets the `packKey` `game|Downloadable Scenarios` (`GAMES_AOE2_DOWNLOADABLE_PACK`, which is also its label) instead of the pack the sheet lists it under, which its row still shows. The DLC are laid out one row per game (`groups`), in the legend's order, which is release order, **each row headed by its game's own box** (the owner's wish, 2026-11-12): the game filter is `groupFilter` of the DLC one, so the view draws it inside the DLC box, one box at the head of each row, and gives it no box of its own, under the heading "Games and DLC". Unticking a game dims its row's DLC but not its own box, and the DLC keep their ticks. **The choice is saved to the account** (the owner's wish, 2026-11-12): the form posts, with the form token, and the route saves what was ticked as JSON in `aoe2_filter` (one row per account, kept to what the sheet offers), then redirects back to `/games/aoe2`. A visit whose address names no filter shows the saved choice, or the defaults with none saved. **An address that names filters** (`?game[]=II&pack[]=II|TC…`) shows exactly those and saves nothing, so a link can be followed without losing your own. **A filter missing from the address, or from the saved choice, takes its defaults, and one that is there takes exactly what it names**; a filter added after a choice was saved is therefore missing from it and starts at its default; each fieldset sends an empty value as well, so ticking nothing still arrives as none. That is what lets a link name one filter and leave the others alone: `?game[]=I` shows every AoE I DLC. It replaced a single `f=1` marker, which made every filter not named in the link come out empty. Filtering happens in PHP, so the suite can see it; `aoe2.js` only submits the form on change, which saves it. A filter that is not "this field is one of these" needs its own predicate in `gamesAoe2Filtered()`.
- **The lanes are laid out in PHP over the shown rows** (`gamesAoe2Lanes()`): a campaign holds a lane from its first shown scenario to its last, takes the lowest free lane, and leaves it empty for one row after it ends, so the next campaign in it never reads as a continuation. To scale it does all of that by year rather than by row (see one row per year, below), so no two campaigns share a lane in one year. **A campaign is its `lineKey`, the game and the campaign name up to its colon** (the owner's wish, 2026-11-13). AoE IV splits its campaigns into chapters that number on from each other (The Hundred Years' War: Chivalry 1–2, Disorder 3–4, Desperation 5–6, Ascendancy 7–8), and so does Battle for Greece across its Achaemenid, Athenian and Spartan parts (1–21), so one line runs through all of a campaign's chapters. The tick key keeps the whole name. On the live sheet every chaptered campaign stays in one lane, in the list and to scale. A campaign shown once is a dot with no line, and keeps the same gap: **a dot never sits straight under a dot of another campaign** (the owner's rule, 2026-11-12). The one exception is a standalone scenario right after one of its own category (two AoE II Historical Battles): it goes straight under it, so a run of one category stacks in one lane, while a run that changes category alternates. **A standalone scenario is a campaign of its own** (`standalone`, a row whose number cell holds a label and no digits): the Historical Battles and Victors and Vanquished share a Campaign cell without being one campaign, so the owner wanted them as separate dots, never joined by a line. The lanes key them by the scenario rather than the campaign, which also catches the two single standalone scenarios, Downloadable Scenario and AoE IV's Intro Tutorial. Their dots follow the same colour rule as everyone else's (a rule making them all white was tried and dropped, 2026-11-12), so the grey Historical Battles are white, Victors and Vanquished red and AoE IV's Historical Battles blue. At most 7 lanes run at once over the whole sheet and 5 for the default filter (2026-11-12). **Each row is banded in its sheet colour, and its dot and lines are that colour made bright** (the owner's rules, 2026-11-12). `routes/aoe2.php` gives each row `colour`, the background, which is the sheet colour as it is (the owner tried 50%, 25% and 10% saturation and went back to it, 2026-11-12), shown at `GAMES_AOE2_ROW_ALPHA` (45%) over the dark page; the view hands that to the stylesheet as `--rowAlpha`, which mixes it in with `color-mix()`, and `marker`, from `gamesAoe2MarkerColour()`: the same hue at full saturation and value, or white when the row colour's saturation is under 5%, a grey with no hue to show (the owner lowered the threshold from 20% to 10% to 5%, and turned black to white, 2026-11-12). The test is on whole channel values (`20 × (max − min) < max`), so no rounding decides which side a colour falls. On the live sheet only its pure greys (`#d9d9d9`, `#b7b7b7`) are under 5%, so 23 of the 547 scenarios get white (2026-11-12): the AoE II Historical Battles, half the AoE III ones and Downloadable Scenario. The faintest pastels get their hue at full strength, so `#d9ead3` (9.8%) is a vivid green. The band covers the whole row, lanes included, as the sheet's rows do. A dot is its row's marker, and a line segment its campaign's latest shown scenario's, so an AoE III campaign coloured act by act changes colour along its line.
  Four things in the stylesheet go with this:
  - text on a band is light (`.aoeRowLight`) or black, whichever `gamesAoe2RowInk()` finds reads better on the colour as blended over black, with the dim parts at 80% of it. **45% is the most at which every colour the sheet used takes light text**, which is what the owner asked for (2026-11-12): at 46% the pale yellow `#fff2cc` wants black. A colour the sheet adds that is paler still would get black text by the same rule rather than unreadable light text. On `#fff2cc`, the brightest band, light text is 4.1:1 and its dim parts 3.3:1; every other band is higher;
  - the gridline is an inset shadow, which takes no room;
  - a line carries one faint 1px edge (35%), black or white, whichever contrasts more with its colour (`gamesAoe2EdgeColour()`, handed to the stylesheet as `--edge`): white along the deep blues, black along everything else. A dot is edged twice, 1px of white against it and 1px of black round that, swapped to black then white on a ticked dot. Both are the owner's choices (2026-11-12), after trying both kinds on both, and thicker double edges. The edges are `box-shadow`s, the one listed first drawn on top. The lines are edged on their sides only, as a top or bottom edge would draw a seam at every row. An unticked dot is filled with its row's colour mixed over black at the same strength, opaque so it hides the line behind it and reads as a ring.
  A scenario with no colour in the map gets a pale one of its own, `gamesAoe2FallbackColour()` (HSV hue, 25%, 95%, with a hue per campaign by its first appearance in the whole sheet, `gamesAoe2Hues()`), so the marker rule applies to it too. That happens on a first load whose HTML fetch failed, or for a scenario the sheet added since the last map.
- **A row's text is in the sheet's columns** (the owner's wish, 2026-11-12): Scenario, Civilization, Campaign (with its number), Game (the sheet's code, `II:R`, its name in the title) and Pack (the code, `-` for a base game), under a heading row, `.aoeHead`, the first `<li>` of the list. **Each column is only as wide as its widest entry** (the owner's wish): the `<ol>` is one grid, year, lanes, the five columns, then Descriptor (at least 4em), Rating (2.5em), Note (at least 6em, `1fr`), which takes what is left, and YouTube (at least 3em), the columns 0.8em apart, and every row, the heading row included, joins it as a `subgrid` (`grid-template-columns: subgrid`, with `.aoeText` a subgrid of the row in turn), so an `auto` column is sized by its entries in every row at once. Measured in Chrome, every cell of all 547 rows starts within a pixel of its heading (2026-11-12). With every game shown the columns reach nearly across, since the AoE IV campaign names are long. On a phone there is no room: the list stops being a grid, each row is a grid of its own with a 4.5em year, the details wrap under the name and the headings are hidden.
- **Every row draws its own piece of each lane** (absolutely placed `<i>`s from `--lane` and `--colour`), which is what lets a row wrap on a phone and still meet the rows above and below. **So a row has no margin or padding**: a gap between rows breaks every line. The dot is filled by `.aoeRow:has(.aoeCheck:checked)`, so it follows the checkbox with no script. **The checkbox itself is hidden** (the owner's choice, 2026-11-12: the filled dot and the blue row already say a scenario is done; a ticked row turns all its text, year to details, `#0000ff` and bold, the owner's choice after greying it; since bold text can wrap differently, a tick lays the to-scale timeline out again), clipped rather than `display: none` so the keyboard still reaches it, with the outline moved onto its row. **The whole row is its click area**, timeline included: `.aoeLabel::after` is a transparent layer stretched over the row (the row is `position: relative`), so a click anywhere on it is a click on the label. That layer also covers the dot's campaign tooltip, which the row's own text repeats. Checked in Chrome at 1280 and 390 px: a click on the year, a dot, an empty part of the timeline, the meta text or the far right edge ticks the row, and a second unticks it (2026-11-12). Checked in Chrome at 1280 and 390 px against the real sheet, where no line misses a row edge by more than half a pixel (2026-11-12). The dots are 1rem, and the lanes 1rem apart on a phone as on a desktop, which leaves about two and a half pixels between a dot's outer edge and the next lane's line; at the 0.8rem phones used to have, the two would overlap.
- **The sheet is not strictly in year order, and the page marks the rows that jump ahead** (the owner's wish, 2026-11-12, after a first version marked the rows that fall back instead). Its author keeps a campaign's scenarios in their own order in places, so Le Loi 5 (1427) comes before other 1425–1426 scenarios and Le Loi 6 (1426). `gamesAoe2OutOfPlace()` flags a row whose year starts after a year below it is over, **among the rows shown**, so the filters decide what counts; it walks up from the bottom keeping the earliest end so far. A range counts by its start against the ends below, so The Fall of Rome (453) before Gaiseric (406 to 455) is in place; a row with no year takes no part. A flagged row's year is always shown, even when the row above has the same one, bold and behind a ↓ (`.aoeYearOutOfPlace`, the arrow a CSS escape in `::before`): no colour would read on every row colour. The years come from `gamesAoe2YearSpan()`, which also gives the to-scale layout its first year.
- **"To scale" lays the timeline out by its years** (the owner's wish, 2026-11-12). A switch in the filter box, `name="scale"`, posted and saved with the filters as `"scale"` in the same `aoe2_filter` JSON (`gamesAoe2Selection()` reads only filter keys, so it never takes it for one); an address naming filters keeps the saved setting. On, the `<ol>` carries `data-scale` and `aoe2.js` lays it out:
  - **One row is one year**: a year is as long as the shortest row on the page, 29px on a desktop and on a 390px phone alike (2026-11-13): a phone's scenario rows wrap, but its year rows do not. The owner first had 2px a year and asked for a row a year.
  - **Each row sits its years below the first row, or straight under the row above when that is lower**, so rows never overlap: a crowded stretch (the three Red Cliffs in 208) looks as it does with the switch off, and the quiet centuries open up. A row with no year is placed only by the one above. Measured in Chrome over the default view, every row a year places sits within a pixel of its year, nothing overlaps and no line has a seam; the page is 114,000px long on a desktop and 186,000px on a phone (2026-11-12), most of it the 1,750 years between Sargon of Akkad and Battle for Greece.
  - **The years are numbers from `gamesAoe2YearNumber()`**, the first of `gamesAoe2YearSpan()`, written on each row as `data-year`: the first year a cell names, negative before the common era whether the BCE is on it or only on the end of a range (`500 to 400 BCE`); `-` is none. Every year in the sheet parses (2026-11-12).
  - **The room is a spacer, `<li class="aoeGap">`, after every row but the last**, with no background and the lines that run on past that row, drawn full height; its height is `--gap`, nothing until the script sets it. A row cannot take the room itself: padding would sit outside the box its lanes stretch to, and the lines would break. The spacer joins the list's grid like a row, its lanes in the second column.
  - **Measured once and written once, around the gaps**: every row's height is read, the gaps worked out with a running cursor, then all written together, so the page is laid out once, not once per row. It reruns on `resize`, at most once a frame, and when the fonts have loaded. **The gaps are never cleared before measuring**: a row's height does not depend on them, and clearing them shrank the page to a tenth of its length for a moment, which moved the scroll position. The owner saw years and stretches far down the page jump (reproduced 2026-11-13: unfolding 1429 threw its header 2,720px off the top of the screen). A click also keeps what was clicked where it was on screen (`keepInView()`), whatever the browser's scroll anchoring does.
  - **The axis runs to the present year** (the owner's wish, 2026-11-13), and the undated scenarios come after it. To scale, `gamesAoe2UndatedLast()` moves every undated row to the end, each part in the sheet's order; today they are already there, the three Art of War series and the tutorials. `gamesAoe2PresentStep()` finds where the undated block starts. The gap before it is `data-present`, or, when nothing undated is shown, a gap after the last step is, named `present` (`GAMES_AOE2_PRESENT_KEY`, which no scenario key can be, since those all hold a `|`). The script opens that stretch to `data-present-year` on the `<ol>`, the server's `date('Y')`, with decade labels and folding like any other, and the fold endpoint takes `present` as a stretch's name.
  - **Each open stretch carries a year axis, and a click folds it to one row** (the owner's wish and mockup, 2026-11-13):
    - **The axis** is a white line down the left of the year column, one long line under the rows (the owner's wish, 2026-11-13): drawn in the stretches, flush against the row above and below, which cover it, and over an unfolded year's rows. Every tenth year is labelled beside it (`2270 BCE`, through `aoe2.yearBce`). A label sits where its year falls, `first + (top + folded) / L` at the stretch's top, which is exact because the row below sits at its own year. Labels are kept half a row clear of either end, where the rows' own years are. To scale, the years move right of the axis by the same room (`--axisLeft` plus 10px), and on a phone the year column widens by it, or the years would wrap.
    - **Folding**: a stretch of at least two rows (`AOE2_FOLDABLE_ROWS`) folds, so a fold always gains a row. Folded, it is one row of black with a kink in the line (an inline SVG, shown by `.aoeGapCollapsed`), and every row below moves up by what it gave back, through a running `folded` offset in the cursor walk. The button is `.aoeAxis`, laid over the whole stretch so a click anywhere on it counts. The gap `<li>` is `role="none"` rather than `aria-hidden`, so the button is reachable by keyboard, and the script enables only the buttons of stretches long enough to fold. Their title gives the stretch's length in years. Folded from inside, scrolled past its start, a stretch becomes one row under the cursor (the owner's wish), or a row down from the top for a click from the keyboard, which has no cursor; otherwise what was clicked stays put. Hovering tints the stretch's own background, which paints under its lines. The button lies over them, so it must stay transparent: the site's `button:hover` fills buttons with `--panelHover`, and on this button that covered the lines in blue (the owner's report, measured 2026-11-13). `.aoeAxis:hover` and `.aoeGroupToggle:hover` are both kept transparent for that reason.
    - **Saving**: folded stretches are saved to the account as a `collapsed` list in the same `aoe2_filter` JSON, through `/games/ajax/aoe2-fold` (`{list: "collapsed", key, on}`), which refuses a key the sheet does not have. The filter form does not send the list, so its post keeps the saved one (`gamesAoe2Settings()` and `gamesAoe2SaveSettings()` read and write the row for both). ## The Sims 2 (`/games/sims2`)

- **The lists are a data file, not a table** (the owner's choice, 2026-11-14): `gamesSims2Lists()` in `app/modules/games/sims2.php` returns them in page order, each a `key`, a `title` and `groups`, a group heading (mostly the pack the items came with, `''` for none) over its item names. A new list or item is an edit there and nothing else. The first lists (packs, neighborhoods, careers, aspirations, hobbies, life states) were seeded from memory, and the owner has since corrected them and added Lifetime Wants and NPC Encounters. The one exception is Vehicle Encounters (below).
- **A tick is keyed by the list's key and the item's name** (`gamesSims2Key()`, `careers|Paranormal`), not its group, so an item can move between groups and keep it. Renaming an item loses its tick on the page, as a renamed AoE scenario does: the row stays under the old key. Two items of one name in one list would share a key, which a test refuses; that is why the pets' careers are named Pet Security and the like, beside University's Show Business. Ticks are rows in `sims2_check`, written by `/games/ajax/sims2-check`, a copy of the AoE tick endpoint that refuses a key no list has.
- **One card per list, in page order, packed onto 16em columns with no holes** (the owner's wishes, 2026-11-15: each card straight under the one above, and the grids not pushed to the bottom). CSS columns could do the first but not hold a card wider than a column, so `packSimsLists()` in `sims2.js` packs a CSS grid instead (`.simsPacked`): rows 2px tall, every card spanning as many as its height and the 1em gap under it take, a grid's card spanning as many columns as its boxes need, and `grid-auto-flow: row dense` letting a later card fill a hole above. It measures once and writes once, and runs again on resize, once the fonts are in and after a tick, since a done item is bold and may wrap. Without the script the cards sit in plain rows, a grid on a row of its own. Measured at 1920, 1280, 1000 and 390px (2026-11-15): no overlaps, and every card 16 to 18px under the one above. The grid boxes are 1.5em wide, not 1.6: at 1.6 Hobbies came to 681px against the 676px two columns give at 1280px, took three and left a hole. Each has its own "N of M" that `sims2.js` keeps up as boxes are ticked. A ticked item is blue and bold, as on the AoE page; on these near-black cards `#0000ff` contrasts at only about 2.4:1.
- **Careers and Hobbies are grids** (the owner's wish, 2026-11-15): a list with `columns` has its items as rows and a box per number in each column set: careers Levels reached 1-10, Chance cards seen 1-10 and T/E levels reached 1-3, hobbies Levels reached 1-10, Chance cards seen 1-6 and Secret lot visited. `limits`, by group, cuts a set down for that group's rows, which is how the pets' careers have levels 1 to 5 and nothing else (the owner wrote both "1-4" and "gaps at 6-10"; 5 is one number to change). A box's key is the row's plus the set and number (`gamesSims2CellKey()`, `careers|Paranormal|level|3`), and `gamesSims2ListKeys()` gives every key a list has, items or boxes, for the counts and the endpoint alike. A grid is too wide for a 16em column, so each grid's card is only as wide as its grid (the owner's wish, 2026-11-15) and spans as many columns as that takes, no wider than the page, scrolling sideways inside its card past that with the names held at its left edge (`position: sticky`). A box a row cannot have is hatched rather than empty, so it reads as not there, not as not done. A row with every box ticked is blue and bold. The site's `th, td` rule borders every cell, so the grid resets that under `:where(.simsGrid)`, which adds no specificity and leaves its own lines winning.
- **Vehicle Encounters is written up on the page, not in the data file** (the owner's choice, 2026-11-15, since the vehicles are poorly documented online). Its entry in `gamesSims2Lists()` carries `'vehicles' => true` and no items, and `gamesSims2WithVehicles()` fills it from `sims2_vehicle`, one row per vehicle with a name and its occasions as a JSON array of strings, in the order added. Every caller that needs the page's keys passes the filled lists to `gamesSims2Keys()`, the tick endpoint included. The write-up is shared: every account sees the vehicles and their occasions, listed under each name, and ticks them for itself. **Only admins edit it, in place** (the owner's choice, after a page of forms was "horrendous UX"), as the AoE fields and music's other names are: a double click on a name or an occasion swaps it for a box, saved on Enter or on leaving it and abandoned on Escape; a − removes one (a vehicle after a `confirm()`), and a + opens a box for another, where Enter saves and opens the next. The name sits inside its tick's label, so for an admin `sims2.js` holds a single click on it for 250ms and ticks only if no second click follows. Every change posts to `/games/ajax/sims2-vehicle` (`add`, `rename`, `occasions` with the whole list, `delete`), which answers with the vehicle's row drawn by `partials/sims2Vehicle.php`, the same partial the page uses, and the script swaps it in. An emptied occasion is dropped. A name another vehicle has in any case is refused, which the NOCASE unique index also enforces. **A rename moves every account's tick** to the new name in the same transaction, since a tick is keyed by name. A delete leaves its ticks, which show again if the name comes back. The list starts empty.
- **The tables went into the existing `games_test.sqlite` by their own statements** (`sims2_check` 2026-11-14, `sims2_vehicle` 2026-11-15), as `aoe2_entry` did, since that file has no live copy to reseed from.
