# Music front end

Scripts in `public/modules/music/js/`. All are classic browser scripts sharing one global scope; there is no bundler and nothing here is executed by the test suite. `songs.js` alone is ~1,700 lines, `addSongs.js` ~1,200, `albumCard.js` ~690.

## Which script is on which page

| Page | Scripts (in load order) |
|---|---|
| every music page | `util.js` (head, from `/js/`), `nav.js`, `colour.js` (from `nav.php`), `tooltip.js` (from `foot.php`) |
| `/music/songs` | `cardLink.js`, `albumCard.js` (both via `albumCardModal.php`, **before**) then `songs.js` |
| `/music/artists`, `/music/albums` | `cardLink.js`, `albumCard.js` only (no `songs.js`; the list pages are static tables) |
| `/music/add-songs` | `addSongs.js` |

`songs.js` calls `writeCardLink`/`cardLinkValue`/`CARD_LINK_PARAMS` from `cardLink.js` and relies on `albumCard.js`'s delegated click listener, so the order is load-bearing (a test checks it). Do not give two scripts the same top-level `const` name: they share one scope (`albumCard.js` and `songs.js` each define their own modal consts under distinct names).

## Small scripts

- **`nav.js`**: `ResizeObserver` on `<nav>` publishing `--navHeight` (via `getBoundingClientRect().height`) to `<html>`; also run once synchronously.
- **`colour.js`**: live preview of the hue slider (`#navColourInput`) writing `--hue` on `<html>`; reverts to the saved hue if the `<details>` menu closes without saving.
- **`tooltip.js`**: delegated `mouseover/out/move` over `#musicTooltip`. Targets: `[data-tooltip]`, or any `[title]` inside a `[data-tooltip-titles]` container (the title is *moved* into `data-tooltip` on first hover; an SVG child `<title>` likewise). `musicTooltip.link(el, text)` for imperative use. Text is `pre-line` so `\n` breaks lines. Hidden on any scroll (capture). Code that rewrites a cell's tooltip must write `data-tooltip` if the element has one, else `title`.
- **`cardLink.js`**: `CARD_LINK_PARAMS = [songCard, albumCard, artistCard]`, `CARD_LINK_MODAL_PARAMS = [albumCard, artistCard]`, `writeCardLink(ownedParams, param|null, id)` (deletes the owned params, sets one, `history.replaceState`), `cardLinkValue(param)` (digits only or null).

## `songs.js` anatomy

Top to bottom (line numbers approximate):

1. **State and DOM handles (1–25).** `songSort`/`songDir` seeded from the URL; JSON blobs from the page (`songArtistData`, `songAlbumData`, `songLinkFieldData`, `songTrackAliases`).
2. **Dual-DOM sync (26–88).** `rowsBySongId` pairs `tbody.children[i]` with `#songCards.children[i]` (positional!). `syncField(songId, field, apply)` applies a change to the cell with that `data-field` in both. `valueElement(cell)` finds the inner text node holder (`.ratingNoteText, .songCellText, .songGateValue`) because widths are enforced on an inner block. `syncResult(songId, msg)` writes the transient Result column/field and toggles `hideResultColumn` on table, card list and modal when nothing is showing a message.
3. **Modal (90–160).** `openCardModal` *moves* the real card node into `#songCardModalBody` and remembers `modalCardReturnAnchor` (the next sibling) so `closeCardModal` can reinsert it in place; refuses hidden cards; `writeCardLink("songCard")`. Prev/next walk visible siblings (`modalNeighbour`). Escape closes; ←/→ step unless focus is in a form control.
4. **Edit-mode editors (163–716).** Admin-only, driven by the card's Edit button (`handleCardEditClick`). `createIdListEditor(config)` builds the shared artist/album multi-select editors (select + remove per row, `+` to add; each change is remove-then-add against `song-artist`/`song-album`). `linkFieldEditor`, `yearFieldEditor`, `durationFieldEditor` swap a field for inputs saving on blur to `song-link`/`song-year`/`song-duration`. Leaving edit mode rebuilds artist/album names as links (`artistNameLink`, `albumNameLink`) so the cards keep opening, and re-renders embeds (`renderSpotifyEmbed`, `renderYoutubeEmbed`, `renderSoundcloudEmbed`, `renderLinkDisplay`). `aliasFieldEditor` turns the Also Known As row into the shared `renderAliasEditor()` rows (see the album card notes), creating the row for a song with one name: "Use this name" posts `song-edit` and runs `applyRenamedTitles()`; an add or a delete writes the returned `names` into `data-titles` on both copies, a delete also dropping the name from `songTrackAliases` (`forgetTrackListing()`); all three then run `applySongTitle()` on the row and the card. `applyAliasCell()` leaves a cell alone while the editor is in it. Leaving edit mode removes the card's row once no other name is left, and an add that lands after Done puts it back. `relationFieldEditor` does the same for the Related row: each relationship with a ×, then a + (`.cardRelationOpen`) that adds a row above itself, as the artist and album editors' + does. Saved and new rows are the same `row()`: a kind `<select>` (each type's two labels from `songRelationTypes`, the value `type:role` for this song's end) and a song box, `<input list="songRelationChoices">`, beside a ×. `relationChoices()` builds that one `<datalist>` on first use from `rowsBySongId` (`Artist — Title · Albums`, ` #id` added to a label that would repeat) and keeps the label → id map; `applyRenamedTitles()` drops it through `forgetRelationChoices()`, and rows read it afresh on every lookup, so a rename is found by its new title. Picking the card's own song is refused before sending, and a refused save of a saved row redraws the card's rows from what is stored (`send()`'s `onRefused`), so the row never shows a relationship that is not there. There is no Add button: a row posts `add`, or `update` with its id, whenever both have a value and something changed; a new row starts on "—" and an empty box, so picking the song first cannot save a kind nobody chose. A suggestion picked from the list saves at once (`inputType` `insertReplacementText`), typing on `change`, and a name matching no song puts a saved row's song back. A new row's × drops it unsaved, a saved one's posts `remove`. The answer carries the lists of every song it changed, and `apply()` redraws each one's table cell (`show()` on the `<tr>`, lines with their text as `title`) and card, so the other songs change too; leaving edit mode redraws the lines (`relationLine()`, whose `relationLink()` writes the other song as `songRows.php` does: its id, then its title in a `.songRelationTitle` span that the stylesheet italicises) and drops an empty row. A line's link opens that song's card through `handleRelationClick()`, or, when the filter hides it, follows its `href` to the unfiltered list. Titles in those lines are as they were at load or at the last answer. The title is edited through the generic cell editor with `TITLE_SPEC` against `song-edit`. Edits patch only the card, not the table row (a reload picks them up); `data-links`, `data-song-year`, `data-fallback-year`, `data-duration` on the card hold current values for re-render.
5. **Card view toggle and column picker (802–841).** `html.songCardView` class, auto-on below 700 px width unless the user toggled manually; a tiny inline script in `songs.view.php` sets it before first paint. The column picker beside it is a `<details>` of checkboxes, each carrying `data-column` and `data-hide-class`. One `change` listener toggles that class on `#songListTable` and chains a `postJson` to `song-columns` onto `songColumnSaves`, so saves go one at a time. A failed save keeps the choice on screen and toasts `song.list.columnsNotSaved`, with no song for the toast to open. CSS hides the picker in card view.
6. **Filter and sort (824–1077).** `songQuery()` rebuilds the address from sort, dir, filters **and the open card params**. `applySongFilter()` hides/shows pairs (`hidden`), `repopulateSongAlbums()` narrows the album select to the chosen artist (or artist-less albums), `applySongTitles()` runs `applySongTitle()` on every row and card, which swaps the title to the album's listed-as alias when an album filter is active and then runs `applyAliasCell()`, which rewrites the Also Known As cell from its `data-titles` as every name but the one now shown. `refreshSongHeading()`. `sortRows()` re-appends paired nodes in new order (blank cells last in both directions, ties by id); `fieldValue()` prefers `data-sort-value`; `compareCells` supports `number`, `duration`, text (case-insensitive). Header links are intercepted and sorted client-side; the mobile sort `<select>`s do the same.
7. **Rating cells (1079–1435).** `EDITABLE_CELLS` maps `.songMyScoreCell`/`.songMyNoteCell` to `song-rating`. `beginCellEdit(cell, spec)` replaces the value with an `<input>`/`<textarea>` (Enter commits, Shift+Enter newline in notes, Escape reverts, blur commits). The score input gets `inputmode="decimal"` and `refuseUnfitInput(input, SCORE_SPEC.fits)`: any edit (typed, pasted, deleted) that leaves something `scoreFits()` rejects, i.e. anything that could not become a score from 0 to 10, is undone by putting back the value and selection from `beforeinput`. Put back rather than stripped, because the score opens selected: a letter that replaced it and was then stripped would leave the box empty, and blur would save that as clearing the score. `songRating.php` checks the same 0–10 rule again. `saveCell` hands rating writes to the outbox (item 11) and, for the title, posts and then writes the server's canonical value, or reverts on failure. A successful rename also goes through `applyRenamedTitles()`, which takes the `titles` the server returns and puts them in `data-canonical-title`, `data-titles`, the title's tooltip and the Also Known As cell. `cell.dataset.pending` blocks poll overwrites while a save is in flight or queued (on both copies of the cell); `isBeingEdited(cell)` blocks them while typing. `colorScoreCell`/`scoreColour` apply the 0–10 ramp to every `.songScoreColoured` cell.
8. **Blind-rating gate (1110–1252).** `songGateOn` from `#songGateSetting`. `applySpoilerGate(container)` (called from `setCellValue`, the single choke point for value changes) recomputes per row or card: scores gated iff the reader's own score cell is empty, notes gated iff their note cell is empty; `SONG_GATE_CELLS` = other raters' score/note cells + statistic cells except `rated`. `setCellGate` toggles `songGated`, injects/removes the `.songGateReveal` pill, strips tooltip/title and the colour class when covered, restores them when uncovered. Reveals are remembered per page session in `songRevealed` keyed `songId:data-field`. `ownValue()` reads a live input so mid-edit typing does not flicker the gate, and falls back to `borrowedValue()`, so a rating borrowed from another version counts as the reader's own; another rater's cell is coverable when it has a real or a borrowed value. The tbody click handler ignores clicks on a pill.
   **Borrowed ratings** (see `music.md`, Statistics) are worked out by the server; the page only writes them. A borrowed value lives in a `.songInherited` span after the value element, so `valueElement()`, the editors and `cellText()` never see it; `setBorrowed(cell, value)` writes it (before `setCellValue`, so the gate run there sees it) and `colourBorrowed()` puts it on the ramp. `applyRatingHalf()` takes the entry's `scoreBorrowed`/`noteBorrowed` and splits the value into the real one and the borrowed one; it is fed by the poll, by `sendRating()`'s `result.ratings`/`result.relatedStats`, and by `relationFieldEditor.send()`'s `ratings`/`stats`. `fieldValue()` falls back to the borrowed value, matching the server's `ORDER BY` over `effective_rating`. The hover list is the page's own: `lendingVersions(songId)` reads the row's Related cell for relationships whose type has `inherits` (`SONG_LENDING_TYPES`), and `refreshVersionTooltips(songId)` writes each rater cell's `data-versions` from what those songs' own cells really hold, leaving out a cell the gate covers for this reader (the reveal pill's handler refreshes the songs it lends to), one `versionLine()` sentence each, kept as `[[piece, bold], …]` with the rating the only plain piece (the template is split at `{value}` before the title goes in) and joined into both the plain tooltip and `data-tooltip-rich`, which `tooltip.js` shows instead (`song.list.versionScore[Mine]`/`versionNote[Mine]`: the reader's own cell says "You", another's takes the name from its note cell's `data-rater-name`, and the version is the type's noun for the other song's end); `refreshCellTooltip(cell)` joins a note's own text and that list into the tooltip, and `setCellValue` (for notes) and `setCellGate` (on uncovering) go through it, so a covered cell keeps withholding the list. It runs on load for every song with a version, after any rater cell's `setCellValue` for the songs it lends to, and after a relationship edit.
9. **Click routing in the table body (1405–1435).** Title cell → open card; other raters' note cell → open card and flash that note; filepath abbr → open card and flash the chip; otherwise generic edit/Edit-button handling. The same handler is attached to `#songCards` and the modal body.
10. **Live updates (1437–1717).** Poll loop (3 s; after >2 consecutive failures back off to 60 s + up to 15 s jitter; 10 s abort timeout; pauses while the tab is hidden and fires immediately on becoming visible). A tick applies `changes` (rewrites score/note cells for both trees unless pending/editing, flashing them), `stats` (`applySongStats`: writes finished strings into the **table row only**, setting `data-sort-value` for mode), then `events` as toasts. Toasts: `#songToasts` (outside `.songLayout` so it never becomes a positional child), lifetime from the account's cog-menu setting in `#songToastSeconds` (`toastSeconds`; 0 is off for rating toasts, -1 means no timer, the unsaved warning keeps `TOAST_DEFAULT_DURATION` under off), max 140, click opens the song's card. The rater's name is drawn in their own hue (`toastName()`, the event's `hue` at the nav swatch's `100%, 60%`). Each toast follows the same gates as the cells (`toastValueCovered`); covered toasts use separate templates because `fillFromTemplate` emits an unmatched `{value}` literally. `TOAST_SHOW_OWN_EVENTS` is deliberately `true` (TOA in `TODO.md`). An answered tick also calls `flushUnsavedRatings()`.
11. **Unsaved-ratings outbox (1726–2056).** `localStorage` `musicUnsavedRatings:<songAccountId>`, entries `{song, field, value}` keyed `song:field`, read fresh each time through `readUnsaved()`/`writeUnsaved()` (in-memory fallback, `unsavedMemory`, once storage refuses). `saveRating()` queues then `sendRating()`, which resolves `saved`/`refused`/`offline`/`login` and never rejects; 10 s abort. `holdRatingCell()`/`releaseRatingCell()` set `pending` and `songCellUnsaved` on both copies. `flushUnsavedRatings()` (load, answered poll, `online`, backing-off timer) first runs `showUnsaved()` to show and mark every queued value and lift stale marks, then sends sequentially, skipping entries already in flight (`ratingsInFlight`). `toastUnsavedRating()` toasts once per song, and the logged-out case once per page. See `music.md` for the rules.
12. **Deep link (end).** If `?songCard=` is present, open it last (rows must be paired and filtered first); clear the parameter if nothing opened.

## `albumCard.js` anatomy

One modal (`#albumCardModal`, ids predate the artist card) hosts two card kinds described by `CARD_KINDS` (`album`, `artist`: endpoint, click trigger selector, dataset key, request param name, link param). Key behaviours:

- `openAlbumCard(kind, id, keepPlace)`: posts `{<param>: id, sort, dir, who}` using page-session state `albumGraphSort`, `albumGraphDir`, `albumStatsWho`; a request counter drops stale responses; `keepPlace` re-renders while preserving the dialog's scroll position; writes the card link before fetching and clears it if the card is missing. Cards are never cached.
- Changing the graph order key resets direction to that order's `data-default-dir`; changing "statistics for" re-fetches. All three re-render server-side.
- Edit mode (admin): album → `loadAlbumOptions()` (first click only, cached promise, retried after failure) then `enterAlbumEditMode` (name, artist, year, other names, track editors); artist → `enterArtistEditMode` (name and other names, no catalogue needed). The editors post to `album-edit`, `album-track`, `artist-edit` and `alias-delete`. **"Done" re-fetches the card** rather than patching. Track alias dropdowns draw on `trackAliases` from the card response and on the `aliases` returned by `album-track` `add`.
- Other names (`cardAliasEditor`): reads every name from the card's `data-alias-names`, which only an admin's card carries, and draws them through `renderAliasEditor()` from `aliasEditor.js`. That script is shared with the song card and draws one row per name after the first, with "Use this name" and a delete that asks first, then a + (`.cardAliasOpen`, styled as `.songEditRowAdd`) that turns into a box (`.cardAliasNew`) posting `alias-add` on blur or Enter; every save redraws the rows, so after Enter the script clicks the fresh + to leave a box open; a song name an album lists comes back `listed`, and the row then offers the button that clears those listings. "Use this name" posts the kind's rename endpoint. The name editors' own renames feed `result.names` back in too, so a rename's old name is deletable straight away. Edit mode creates the row when the card had none, since the + needs somewhere to be.
- Wheel over `select.cardWheelSelect` steps the option (debounced, passes through at the ends so the card still scrolls).
- One delegated `document` click listener opens a card from any `[data-album-card-id]` / `[data-artist-card-id]`, or from a `.songAlbumCell` / `.songArtistCell` whose first link carries the id; ignored for modified clicks and clicks on form controls.
- Escape handling is capture-phase and stops propagation so the song modal beneath stays open.
- Deep link on load for `?albumCard=` / `?artistCard=`.

## `addSongs.js` (the import wizard)

Four stages, each a table built from the previous stage's server results, each with its own submit button; once a row is handled it gets `.rowHandled` and is disabled; a failed `buildNext` shows `status.nextStepFailed`.

1. **Paste and column mapping.** `parseRawLines` (tab separated), a mapping row per column with a role `<select>` (`ignore, artist, title, album, track, year, duration, spotify_url, youtube_url, soundcloud_url, bandcamp_url, filepath, other_url`). `guessRoleForColumn` is content-first (`M:SS` → duration; Spotify URL or 22-char id; YouTube URL or 11-char id; soundcloud/bandcamp hosts; any http URL → other) and falls back by position to artist/title/album/track for the first four columns. A role can be used once (`onColumnRoleChange` demotes the previous holder to `ignore`); `artist` and `title` are mandatory. Output: `pastedRows[] = {Artist, Title, Album, Track (int|null), Year, Duration, Links{role: value}}`; rows with no artist are dropped.
2. **Artist match** → `POST artist-alias`. Each distinct pasted artist gets a select (existing artists, skip, new, custom name, or "same as pending row X": resolved recursively by `resolveRowTarget`, depth-limited) and a keep-pasted-spelling checkbox. Results feed `artistIdByProvidedName`.
3. **Song match** → `POST song`. Per row: existing songs of that artist, new, custom name, skip, and on a row whose title one of them already has, `<New, separate>` (`SONG_OPTION_SEPARATE`; the row keeps the matched song in `data_matched_song_id`). A title several of the artist's songs have is settled by `matchingSong()`: the one on the row's pasted album (`song_albums[id].names`, from the artist step's answer), or none, in which case the row starts on `<Choose a song>` (value `""`, the select marked `.songSelectUnchosen`) and Submit shows `addSongs.chooseAmbiguous` and sends nothing while any such row is left. `data_preselect` holds what the row started on. `songOptionLabels()` labels every existing song `139: Title · Album`, its id first and its albums after, which is also what tells two songs with one title apart. Above the table, `#songSeparate` shows while any row has a match: its `#songSeparateAll` checkbox sets every matched row not yet sent to separate, or back to `data_preselect` and then `refreshSeparateControls()` ticks, clears or half-fills the box from the rows; it reads every matched row, so it runs once after a loop (the table's build, the box's own toggle) and from a row's change listener, never from `syncSongRow()`. While any row is on separate, `#songSeparateRelation` in the same block offers one relationship for all of them, from `songRelationTypes`, sent with each such row as `related_song_id`, `relationship_type` and `relationship_role`; results (`song_id`, `song_alias_id`) stored in `latestSongResults`, joined back to pasted rows by the key `artist_id + "\t" + provided_name` (`songResultsByKey`).
4. **Extras** (shown only if any row has links/year/duration) → one `song-link`/`song-year`/`song-duration` write per value, in parallel per row. Then **Album** → `POST album`. Extras deliberately precede Album so the confirmed year pre-fills the album year. Track numbers: explicit numbers are kept (including 0 and gaps), blanks take the lowest free positions in paste order (`assignTrackPositions`).

State lives only in the DOM and a few module-level maps; reloading or editing the textarea resets the wizard (`handlePasteInput`).

## Writing front-end changes safely

- Any new per-song value shown in both table and card must carry `data-field` on both cells and be written via `syncField`/`setCellValue`.
- Anything covered by the blind-rating gate must be added to `SONG_GATE_CELLS` *and* gated server-side in `songRows.php`, with a test. Remember the CSS id-prefix rule for hiding.
- New server-rendered cards: add to `CARD_KINDS`, an endpoint, and a partial; reuse the shared chrome classes and `scoreStats.php`/`scoreGraph.php`.
- New user-visible text: catalogue key in all three locales (English required, others may start blank), referenced as a literal `t('key')`.
- You cannot run any of this: re-read the diff carefully for global-name collisions and DOM assumptions, and tell the owner it needs a manual look.
