# The mtasa module

Imported by `CLAUDE.md`.

Added 2026-11-16: the owner's catalogue of about 6,800 old MTA:SA maps (`z(2)` to `z(6796)`), moved off a Google sheet that had outgrown itself. The owner deprecates the sheet once the site holds the data. Deployed 2026-11-18; the import on the host is still to do (MTS).

- **Its own accounts, copied from games**, as games' were from hideandseek: `sessionScope('mtasa')`, `mtasa.sqlite` / `mtasa_test.sqlite`, its own catalogue (English only) and stylesheet, the first account an admin, the rest by invite; the register page says under the invite code that one is needed, that an account is for commenting (reading needs none), and to ask the administrator for a code (`register.inviteNote`, 2026-11-18). That makes a fourth set of near-copies (SHR). Everything is `mtasa`-prefixed except the ajax body helpers, which keep music's names.
- **Public to read, and every page `noindex`** (the owner's choices), through the meta tag in `views/partials/head.php`. Unlike games, nothing needs a login to read; a login is for commenting, and an admin for editing and the import. Logging out lands on the list.
- **`001_create.sql` shipped on 2026-11-18 and is frozen**: a schema change is a new `002`, and a deploy ships at most one new migration, music's rule. An edit to a shipped file is a silent no-op on every database that has run it.

## The data

- **Three tables, split as the sheet was.** `map` is the owner's own columns (the sheet's Numbered tab), `map_analysis` what the owner's analysis script found in each map's files (`app/modules/mtasa/import/classics.csv`, which `tools/mtasa/analyze.py` writes, since 2026-11-17; it was the sheet's AI tab, a pasted copy of it), and `map_geometry` where each map starts and its checkpoints (`app/modules/mtasa/import/points.csv`, which `tools/mtasa/points.py` writes, since 2026-11-18; it was the sheet's Mapgen tab), all keyed by the map's number. The script's two are kept apart from the owner's so a later run of it can replace them without touching the owner's fields. **How the script made every one of its columns, and how to run it, is `mtasa-analysis.md`**; the script itself is `tools/mtasa/` (moved into this repo from MTASA-Maps, 2026-11-17). The sheet's New Name is `custom_name`. `map_geometry` holds two JSON arrays as text, re-encoded compact, in GTA world metres to 0.1 m: `spawnpoints`, one point, `[[x, y]]`, the middle of the spawn grid (or none), with a third number, `[[x, y, r]]`, on a map with no checkpoints: the furthest spawnpoint from the middle, the arena's radius (1,716 maps, 2026-11-18), and `checkpoints`, `[[x, y], …]` in race order, x and y only (the owner's choice, 2026-11-18: every spawnpoint, the colours, the pickups and the heights come from the map's files on GitHub on Increase detail). It has a row only for the maps with a folder (6,504 of 6,796). A database written before 2026-11-18 holds every spawnpoint with its rotation and the colours until reloaded, which `mtasaPreviewData()` averages and drops, and keeps its old NOT NULL `pickups` column, which `mtasaWriteGeometry()` fills with `[]` (a column `001`, now frozen, cannot drop).
- **`fields.php` holds every column once**, `mtasaFields()`: its table, the sheet header the import reads it by, its type, the map page's section and whether the admin edits it (only `map`'s are editable). The import, the map page, the edit endpoint and the comment targets all read it, and it is the only way a column name reaches SQL. `mtasaFieldValue()` reads a value as the sheet or the editor writes it: `TRUE`/`yes` and `FALSE`/`no` as booleans with the script's `null` as none, `100%` as 100, a video as an http(s) link. Statuses and gamemodes are lists in code (`MTASA_STATUSES`, `MTASA_GAMEMODES`, the sheet's own), which the editor holds a value to and the import does not, so a stored value outside them still shows as itself. The sheet's Laps and Armed vehicles are not read (the owner dropped both, 2026-11-17). An integer of more than 18 digits is stored as SQLite makes it, an approximate number: the script measured one broken map's route (2658) as 38 digits long, and refusing it would refuse the whole import.
- **Not stored, worked out** in `mtasaDuplicates()`, once per request over the whole catalogue (6 ms for every map):
  - A map's **parent** is the owner's Duplicate of when set, else the script's closest copy (Duplicate of (closest)). A map whose Duplicate of is its own number is an original, whatever the script thinks. Following parents ends at the set's **original**, with a guard against loops and against a parent that is not a map.
  - **Copies** are every map whose chain ends at an original, in id order. They reproduce the AI tab's Copies of this map and Duplicate columns exactly when there are no overrides; 11 of the 6,795 differ on the real sheet, by the owner's overrides.
  - **The word for a copy** is its place in the set, in the sheet's words up to decuplicate (the 10th of a set), then on in the same Latin, as the owner asked: undecuplicate, duodecuplicate … vigintuplicate, unvigintuplicate, up to the 99th, and "100th copy" past that (`mtasaDuplicateWord()`). The sheet itself said "11th copy".
  - **Actual No. is gone**: not read, kept or shown (the owner's choice, 2026-11-17), and dropped from the sheet itself on 2026-11-18.

## The import

- **Once, by an admin, from a button that is there only while the site holds no maps** (the owner's design). `/mtasa/import` posts the form token; `mtasaImport()` reads three CSVs: the sheet's Numbered tab (`MTASA_SOURCE`, a public export needing no key, curl with the system CA store as games does) and the repo's `import/classics.csv` and `import/points.csv` (the owner's choices, 2026-11-17 and 18, now that the site holds the tools; the AI and Mapgen tabs had them pasted, which Sheets had reformatted in places, "4.0" as 4 and 06:00 as 6:00), finds columns by header and refuses the lot over a missing column, a bad Number or folder, a repeated one, a value its type cannot read, or a points.csv cell that is not a list of well-formed points (`mtasaReadMapgen()`: two numbers each, x and y, and at most one spawn point), naming the map and column. points.csv names a map by its folder, `z(N)`. The write is one transaction that first checks all three tables are empty, so a double click or two admins at once import once. A map only classics.csv or points.csv has still gets its `map` row. Nothing writes the sheet. The real sheet took 5.4 s through the button when it still fetched the 11.6 MB Mapgen tab (2026-11-16); points.csv is 3.1 MB.
- **Comments on the sheet are not imported**: Google's public exports do not carry them.
- **Reload the analysis**, under the list, for an admin once there are maps: after a rerun of `tools/mtasa`, it replaces every `map_analysis` row from `classics.csv` in one transaction (`mtasaReloadAnalysis()`, the import page's `action=reload`), the owner's columns, the points and the comments untouched, and adds an empty `map` row for a map only the file has. It is how a change of format reaches a catalogue already holding the owner's work, as the vehicles and zones by id did on 2026-11-17.
- The suite feeds the import copies of `tests/fixtures/mtasa_numbered.csv`, `mtasa_ai.csv` and `mtasa_mapgen.csv` through `LOTSOFS_MTASA_SOURCE`, `LOTSOFS_MTASA_AI_SOURCE` and `LOTSOFS_MTASA_MAPGEN_SOURCE`. The fixtures are 169 real maps: 2–5 and 78–230, every copy in the sets of 78 and 87 (so the 11th and 12th of 87 are there), and 2296 for its 1,704 checkpoints. Copies, because tests break a header or a cell and put it back.

## The pages

- **`/mtasa`, the list**: a GET form of filters, sortable header links and pages. **The pager** (the owner's layout, 2026-11-18), above and below the table, is « First, ‹ Previous, a box to type the page into ("Page [ 3 ] of 68") and a Go button beside it, Next ›, Last », and Per page, 10, 25, 50, 100, 250, 500 or 1000 (`MTASA_PAGE_SIZES`, 100 the default, `MTASA_PAGE_SIZE`). It is a GET form, its hidden fields carrying the filters, search and sort, so Go and Enter work with no script, and Go also submits a new size where no script does; a link with nowhere to go stays in place, greyed (`.mtasaPagerOff`, `aria-disabled`), and the pager shows whenever there are maps, so the size can be changed on a single page too. Changing the size reloads at once, on the page that keeps the first map showing (`floor((page − 1) × old / new) + 1`), and the size travels: `mtasaListUrl()` adds `per` when it is not 100, so the sort headers, the pager's links, the filter form (a hidden `per`) and Clear keep it, and the route takes any whole number from 1 to 10,000 (`MTASA_PAGE_SIZE_MAX`), else 100, so an address can ask for a size the dropdown does not offer, which it then shows in its place, chosen (the owner's wish, 2026-11-18). Checked in Chrome: typing 3 opens page 3, picking 25 on page 2 of 100 lands on page 5 with the same first map, Last goes to the last page, and nothing scrolls sideways at 390 px. **The filters are remembered in the browser** (the owner's wish, 2026-11-16), by an inline script at the top of `index.view.php`, before the table is parsed so the bare list never shows first: a visit to the bare `/mtasa` (the nav, "All maps") goes to the saved filters with `location.replace`, any other visit to the list saves the filters and search in its address as `mtasaListFilters` in `localStorage` (none forgets them), and Clear (`data-clear-filters`) forgets them. Sort and page are not kept; the page size is, but not the default the pager's form always sends. Everything else on the list works without the script, and a browser that refuses storage just remembers nothing (checked in Chrome). The filters are definitions in `mtasaFilters()`, their options read from the catalogue, so a value the data brings is offered at once; a values filter's `none` is the maps with nothing there, except Finished's (`binary`), which is only Yes and No, an unmarked map counting as No (the owner's wish, 2026-11-18). **Gamemode filters as the column shows it**, a map's gamemode else the script's guess (`MTASA_GAMEMODE_SQL`, the sort's expression too), so there is no Gamemode guess filter (the owner's wish, 2026-11-18). **Errors leaves out `folder missing` by default** (the owner's wish): a filter's `hidden` values (`mtasaFilterDefault()`) are left out while the address does not name the filter, and its boxes start ticked but for them. The form names it with an empty `errors[]=` beside the boxes, so unticking all of them means every map; a choice equal to the default reads as no choice, and an empty one is written back as `errors[]=` by `mtasaListUrl()`, the pager and the memory script. The search is a `LIKE` over the names, title, author, descriptions and folder, with `%` and `_` escaped, and a number also matches that map. `mtasaListQuery()` filters and orders the ids first, in SQL where it can and in PHP for the original and the Duplicates filter, which only the chains know, then reads the one page's rows by id. **Blanks sort last in both directions**, the site's rule. The number cell opens the map, all of it a link, and so does the name, whose hover box says where the name comes from (`mtasaNameSourceText()`: the custom name, the original name, the gathered name with its source, or the folder). A gathered name is the script's guess and shows faded and italic, as the gamemode's guess does (the owner's wish, 2026-11-17). The status and the gamemode are coloured as on the map page, the gamemode where the race mode was, falling back to the script's guess, faded, while none is set, and Finished is a ✓ (the owner's wishes, 2026-11-17), all sortable. Finished and the video come after Checkpoints, before Errors (the owner's layout, 2026-11-18), the video a ▶ that opens it in a new tab, with the link only in its hover box, so it never widens the table. **Warnings** comes after Errors (the owner's wish, 2026-11-18): the script's warnings on one line, cut off at 16em with the whole text in the hover box, after a yellow ! when any of the map page's three pairs differs, the title from the original name, the gamemode guess from the gamemode or the duplicate guess from Duplicate of (`mtasaGuessMismatches()` in `maps.php`, the view's rule), its hover box naming which. The GitHub ! marks cannot show there, since they exist only once Increase detail has fetched that map's files. The column sorts by the warnings text alone. The author column is cut off at 10em, with the whole text in its hover box (the owner's wish: some authors are a sentence of credits), and the custom description, the last column, at 16em on one line, the same way. Race mode, Spawnpoints and Start city are not columns (the owner's choice, 2026-11-17), and Race mode is still a filter (Start city went with its column, 2026-11-17).
- **An admin edits the list by clicking a cell** (the owner's wish, 2026-11-17; `js/list.js`, loaded for admins only): the status, the gamemode and the custom description open a box (a dropdown for the two lists, from the table's `data-choices`), saved on Enter or on leaving it and abandoned on Escape, and Finished is a checkbox, ticked by a click anywhere in its cell. ## Comments

- **Anyone signed in comments on any field, the script's included, or on the map in general**, in threads with replies (the owner's choices, 2026-11-16, standing in for the sheet's comments). Everyone reads them, signed in or not. `map_comment` keys a thread by map and `field` (a registry key, NULL for the map), and a reply by `parent_id`; replies do not nest.
- **Who may do what**, in `comments.php`: only the author edits (shown as "edited"); the author or an admin deletes; the thread's author or an admin resolves and reopens. A thread's first comment deleted under replies stays as "Comment deleted", its text gone, so the replies keep their context; once its last reply goes, it goes too. Resolved threads fold away under "N resolved".
- **`/mtasa/ajax/comment`** is one endpoint with an `action` (`add`, `edit`, `delete`, `resolve`, `reopen`). It answers with that field's threads drawn by `views/partials/threads.php`, the partial the page uses, which the script swaps in, and the open count for the field's badge. A reply must be on its thread's map and field. Bodies are escaped and shown `pre-line`, up to 2,000 bytes. Enter sends, Shift+Enter breaks the line.
- **On the page**, a field with threads has a 💬 badge with its open count, and for a signed-in reader an empty field has a + that shows on hover (always on touch screens). Either unfolds that field's threads, one field at a time: beside the field where the main column has room for both (a container query at 64em, which narrows the fields to make room), under it otherwise. A thread on a field whose key the registry no longer has is kept but not shown.
- **`/mtasa/comments`** lists threads across every map by latest activity, open only unless asked, each linking to its field (`#field-status`, which opens it) or the map's own comments. It is how the admin sees what is new among 6,800 maps. The list's Comments column and filter count open threads.
