# The hideandseek module

Imported by `CLAUDE.md`.

Boilerplate, added 2026-09-28: the account system and page chrome, with no game in it yet. It is deliberately a *copy* of music's shape rather than a shared framework — this codebase has no service layer and factoring one out of two modules before the second one has any features would be guessing at what they share.

- **Its own everything.** `sessionScope('hideandseek')` (so its accounts are unrelated to music's — a person signed in to one is signed out of the other, in the same browser, and a test pins that), its own `hideandseek.sqlite` / `hideandseek_test.sqlite`, its own `schema_migrations`, its own catalogue, its own stylesheet and its own language (see the preferences note below). Not its own hue: the theme is fixed, and the note below says where its colours live. `001_create.sql` has shipped nothing yet, so it is still editable; the moment it deploys, the same freeze rule as music applies. **Editing it is not free even now**: migrations are tracked by filename with no content hash, so any database that already recorded it will not re-run it, and the change silently never lands. The suite will not catch that — `tests/run.php` copies the repo excluding `.sqlite` and starts fresh every run — so the only casualty is a dev database, where the symptom is a 500 on a table that was never created. Reset it in the same pass: delete the file, or `DELETE FROM schema_migrations WHERE filename = '001_create.sql'`, which re-runs it and keeps the accounts, since every statement in it is `CREATE … IF NOT EXISTS`.
- **Functions are `hns`-prefixed** (`hnsAccount`, `hnsIsAdmin`, `requireHnsAccount`, `hnsGenerateInviteCode`, `hnsLoginIsBlocked`, `runHideAndSeekMigrations`), *except* the ajax body helpers `ajaxInt`/`ajaxText`/`ajaxTrimmed`/`ajaxNumericText`, which keep music's names. One route or endpoint runs per request, so the two copies never meet — but that is the assumption, and requiring both guards in one request would be a redeclaration fatal.
- **One fixed theme, and it is light** (it was dark until 2026-09-30). The whole palette is ten custom properties on `:root` in its stylesheet — `ink`, `inkDim`, `ground`, `panel`, `panelRaised`, `border`, `accent`, `accentDim`, `danger`, `imported` — and every rule in the file reads one of them, so the theme turns over by editing that block and nothing else. There is no per-account hue as music has, so a colour belongs to the site rather than to whoever is looking. Three things carry colour **outside** that block and have to be moved with it: `json/mapStyle.json`, which paints the basemap and is the only place the map's own colours exist (the layer notes in its `metadata` describe the choices, and it is meant to be edited in Maputnik); the marker colour in `js/map.js`, which MapLibre takes as a value rather than from CSS (the imported-POI markers get round this by reading `--imported` off the root with `getComputedStyle` at load, as the fallback for a category with no colour of its own, so that one does follow the block); and MapLibre's control icons, which ship dark and were being flipped by a `filter: invert(1)` that light mode does not want. Its white icons are guarded by `forced-colors: active`, not `prefers-color-scheme`, so a reader's OS theme cannot bring them back.
- **A pasted-in map style must be repointed before it renders.** `json/mapStyle.json` is OSM Bright, 128 layers. Upstream copies of any style ship pointing at whoever published them, carrying that vendor's API key, and render a completely blank map here — two foreign styles arrived this way on 2026-09-30 (AWS Location, then MapTiler's own OSM Bright) because Maputnik's Open dialog offers gallery styles right beside the upload button. Repointing is two fields: `sources.openmaptiles.url` to `https://tiles.openfreemap.org/planet` and `glyphs` to `https://tiles.openfreemap.org/fonts/{fontstack}/{range}.pbf`. Anything on the OpenMapTiles 3.x schema then works untouched, and the Noto Sans stacks those styles ask for are the three OpenFreeMap serves. A test pins both properties — every tile and glyph host must be OpenFreeMap, and the file must contain no credential-shaped string — so a paste that forgets fails the suite rather than the browser. The **sprite is the deliberate exception**, still `openmaptiles.github.io`: icon names only match the sheet they came from, so swapping it would empty the 11 layers using `icon-image`. Bus routes cannot be drawn from these tiles — a bus route is a `type=route` relation and nothing in the tileset carries one. (Not quite "no relations at all", which the notes used to say: `transportation_name` has `route_1_*` … `route_21_*` fields, and a z14 tile over Groningen fills them with `rwn`/`nwn` walking networks. Route relations do reach the tiles, just not bus ones, so a road carrying a bus route is indistinguishable from one that does not.)
- **The base map writes no text at all.** Since 2026-10-04 the only labels on the map are the imported POIs' own; every label the style draws — street and place names, transit stops, airports — is switched off. `hnsHideLabels()` in `js/map.js` walks the style once at `load` and sets `visibility: none` on each layer that passes **two** tests, and both earn their keep. First `type: symbol`, rather than source layer: two source layers carry labels *and* geometry — `waterway` has `waterway-name` beside the canal lines, `transportation` has the one-way arrows beside the roads — so the obvious simplification of hiding those source layers wholesale would erase the canals and the roads along with the text. A test pins that mixture. Second, the layer must have a **`text-field`**: a symbol layer without one draws only an icon, and in this style that is exactly the two `road_oneway*` layers, so the one-way arrows survive without being named. A test pins that they carry no `text-field`. Visibility rather than `removeLayer`, so a re-pasted style needs nothing maintained here and nothing is destroyed.
  This replaced an allowlist (`HNS_LABEL_SOURCE_LAYERS`, `HNS_KEPT_CLASSES` for bus/railway/ferry, `HNS_KEPT_SOURCE_LAYERS` for airports) and the **list of drawn places** under the map, which read `queryRenderedFeatures` on every `idle`. With nothing of the base map's labelled, that list had nothing to list, and it went with the rest; a test checks the old names are gone rather than left dead.
- **Imported POIs are on the homepage, in the map and in the list beside it.** `routes/index.php` hands every POI on the loaded game map to the page as a JSON `<script>` — only to a signed-in visitor, because `hnsLoadedGameMap()` honours `?map=` and the homepage is not behind a login. It is encoded with the `JSON_HEX_*` flags: the names came from a stranger's paste, and a raw `</script>` in one would end the tag. The JSON is `{categories, pois}`, each POI naming its category by id, so a colour and icon travel once per category rather than once per POI.
  `js/map.js` draws them as a GeoJSON source and **one symbol layer**, `hnsImportedPoints`, added after `hnsHideLabels()` has run, so the blanket label rule never sees it. **Emoji cannot go in a `text-field`**: MapLibre draws text from the style's glyph PBFs, which hold no emoji. Each category's marker is therefore drawn once to a canvas by `hnsPoiIconImage()` and registered with `addImage` at pixel ratio 2, and the layer's `icon-image` picks it per feature. The marker is the icon as bold **text**, outlined in the category colour and filled **white when that colour is dark and black otherwise** (`hnsIsDark()`: whichever of the two the colour has the higher WCAG contrast against, i.e. relative luminance below ~0.18); with no icon it is a plain dot of that colour.
  Text rather than the colour emoji is deliberate, and it takes two things together: `hnsTextPresentation()` strips any `U+FE0F` and appends `U+FE0E`, and the font stack (`HNS_ICON_FONT`) leads with symbol fonts. Chrome then draws an emoji as a one-colour glyph in `fillStyle`, so a letter and an emoji look like the same kind of thing. The one exception is a ZWJ sequence (👩‍⚕️), which has no text form and stays in colour. The list's group headers carry the very same marker, drawn into a `<canvas>` by `hnsIconCanvas()`, with the category name in the ordinary ink colour — a header written *in* the category colour was illegible for light ones (grey, light green, yellow) on the header's light ground. The icon inputs get the text presentation through `font-variant-emoji: text` plus the symbol font — on `input.hnsIconInput`, because `input[type="text"]` sets `font: inherit` and outranks a bare class. (The first version drew the emoji inside a white disc, which hid letters entirely: a letter takes `fillStyle`, which was still the disc's white, while a colour emoji ignores it.)
  The name rides on the same layer from z13 as optional bold text (labels still collide with each other, so a zoomed-out map just shows fewer of them) styled the **other** way round from the icon: the text in the category colour, with a 1px halo that is white **unless the colour is genuinely light** (`hnsLabelHalo()`: contrast against white below 3:1, e.g. yellow), carried on each feature as `halo`. Deliberately **not** `hnsIsDark()`'s even split: a saturated mid-tone such as `#ff0000` contrasts slightly more with black (5.3 vs 4.0), and red text in a black halo on a light basemap was measured unreadable at both 2px and 1px. The icon can use the even split because its coloured outline already separates it from the map.
  The list, `#hnsImportedPoiTable`, is **built once at page load** and holds every imported POI whether in frame or not, one `<details>` per category. Clicking a row rings the place with a DOM marker and pans the map to it when it is out of frame (`hnsFocusPoi()`). The list is there before the map is loaded, since it needs no tiles; a row clicked then is held in `hnsPendingPoi` and focused once the map is ready, which is tracked by `hnsMapReady` rather than `map.loaded()` — that reads false for a moment after `addSource`, and the pending focus would be dropped. Clicking a row never loads the map by itself: nothing reaches the tile server until the button is pressed.
  **One overlay at a time, of two kinds.** Each category header has two buttons, ⬡ (nearest-area borders) and ◎ (distance circles), and at most **one** of all of them is on: `hnsOverlay` is `{kind, category}` or null, `hnsSetOverlay(kind, id)` turns the pressed one off if it was already on and otherwise replaces whatever was on, of either kind, and the choice is deliberately **not** remembered: every visit starts with no overlay, while the category and unnamed toggles do persist. Both kinds draw into the same `hnsOverlay` source and its two line layers, and `hnsUpdateOverlay()` is the one recompute everything calls — the category checkbox, the unnamed toggle, layer setup, and adding or removing a pin. The POIs either kind uses are that category's, filtered by the unnamed toggle and by nothing else: in frame or not, they all count; a hidden category draws nothing.
  **⬡ draws the borders of the category's Voronoi diagram**: every line is where the nearest POI of that category changes, so the map is split into the area each one is closest to. **Neighbouring areas of POIs with the same name merge**: every border belongs to one pair of neighbouring POIs (a Delaunay edge), and `sameName()` skips it when both carry the identical, non-empty name — one hospital mapped as two buildings is one place to a player. An empty name is never "the same" as another, so unnamed POIs keep their borders. Exact match, case and all: "Erasmus MC" and "Erasmus MC - Sophia" stay apart. On the Randstad hospitals this removes 4 of 130 borders, one per duplicated name. The diagram comes from **d3-delaunay**, vendored at `vendor/d3-delaunay/` (19KB, Delaunator bundled) and injected by `hnsLoadDelaunay()` the first time it is needed, as MapLibre is. **It is computed on the sphere, not on the flat map.** "Nearest" is by great-circle distance, and `hnsNearestLines()` gets there in three steps. The POIs become unit vectors and are **stereographically projected** from the point opposite their centroid; that projection maps circles on the sphere to circles in the plane, so d3's flat Delaunay triangulation of the projected points *is* the spherical one. Each triangle's border corner is then its **spherical circumcentre** (`hnsCircumcentre()`: the normalised cross product of two edges, flipped into the triangles' hemisphere), not d3's planar one, which projection does not preserve. And each border is a **great-circle arc** between neighbouring corners, cut into ≤0.25° steps (`hnsArc()`) because MapLibre joins vertices with straight Mercator lines. Hull edges become rays along the bisecting great circle, pointing away from the triangle's third vertex, 10° long — far off any screen that shows the points. All the points on one line (and exactly two points, for which d3 returns a stand-in triangle rather than flagging them collinear) take a separate path: plain bisectors between consecutive points. Measured with brute-force haversine over every vertex drawn, the two nearest POIs are equidistant to the millimetre; the flat version this replaced (longitude scaled by cos(mean latitude), then d3's planar Voronoi) was off by up to 57 m on the Randstad hospitals and 805 m on points spread across the country. The sphere, not the ellipsoid: the remaining error is the Earth's 0.3% flattening, which moves a border by metres at most over a city. It uses exactly the POIs the map is showing for that category — hiding the category clears it, and the unnamed toggle changes which places take part — and needs at least two. The lines are a casing in the label's halo colour under a 2px line in the category colour (`hnsNearestCasing`, `hnsNearestLines`), both inserted *beneath* `hnsImportedPoints` so the icons sit on top. The pressed button is filled with the category colour, its glyph black or white through `--groupInk` from `hnsIsDark()`, since a white glyph on yellow would vanish.
  **◎ is the measuring question: circles at the latest pin's distance.** It takes the **most recently placed pin** (`hnsMarkers[hnsMarkers.length - 1]` — pins live only in the page; removing the latest falls back to the one before), finds the great-circle distance *r* to the nearest POI of the category, and draws a circle of radius *r* around **every** POI of it, merged into one outline: the area closer to one of them than the pin is. The radius shows in the header beside the button ("749 m", "1.24 km"), or "Place a pin". Outline only, no fill, which is what kept it library-free: `hnsCircleLines()` samples each geodesic circle at 128 points, drops the samples that fall inside another circle (`dot(p, c_j) > cos r` — a dot-product comparison rather than `acos`, which stays precise at street scale; neighbours are pre-filtered to centres within 2r), and keeps each uncovered run as a line, **bisecting** each covered/uncovered transition to land the run's end on the exact crossing so neighbouring arcs meet. What survives is exactly the union's boundary, holes included. Identical POI positions are merged first, or each would count the other's circle as covering its own and both would vanish. Measured by brute force over every vertex drawn: the nearest POI is *r* away to within 0.03 mm, including a ring that leaves a hole (inner arcs drawn) and a POI swallowed by its neighbours (no arc of its own).
  The two buttons and the distance sit in `.hnsPoiGroupActions`, **absolutely positioned against the header's top and bottom edges**, with the buttons square through `aspect-ratio`. That is what lets them fill the bar: the header's height comes from the 30px icon canvas rather than the text (and is less for a category with no icon), so sizing buttons from the font never matched it. The header reserves room on the right for them (more, through `:has()`, while a distance is showing). Not flexbox on the `<summary>` itself, which would drop its disclosure triangle in Chrome.
  **Hide all / Show all** above the list flips every category's checkbox at once: hide while any category is shown, show once none is. The category checkbox is sized to the overlay buttons (2.2rem) with negative vertical margins, so it fills the header without making it taller — a taller header would stretch the buttons, which track its height.
  **Two toggles, both one layer filter.** Each category header has a checkbox that hides that category on the map (its group stays listed, dimmed), and above the list one checkbox shows or hides places **without a name** across every category — hidden by default, since a nameless point is mostly clutter. `hnsApplyImportedFilter()` sets a single `setFilter` on `hnsImportedPoints` from both, reading `category` and `named` off each feature, so neither repaints anything but that layer. The checkbox sits inside `<summary>`, which is safe: the click activates the checkbox, not the summary, so ticking it does not fold the group (checked in Chrome). The unnamed toggle rebuilds the groups, because counts and empty categories change, and keeps open groups open through `hnsOpenCategories`; it lives outside the rebuilt container so it keeps focus. Both choices are per-viewer conveniences in `localStorage` (`hnsHiddenCategories`, a list of category ids — unique across maps, so one list serves them all — and `hnsShowUnnamed`), read and written through try/catch helpers so a browser that refuses storage just gets the defaults.
- **The map and the list of places are two columns past 1200px, stacked below it.** `index.view.php` wraps each half — heading, map, hint on one side; heading and `#hnsImportedPoiTable` on the other — in `.hnsMapLayout`, a column flexbox that turns into a row in the one `min-width` media query the stylesheet has. **The map is square** — `aspect-ratio: 1 / 1`, so its height comes from its width and not from the viewport; a letterboxed map wastes the zoom it has. It still has a definite height, which MapLibre requires: it measures its container and draws nothing at all in a box that sizes itself from its content. The cap on it is `--mapMaxSide` (`80vh`), applied as a **`max-width`** on both the map and its column — a `max-height` would clamp the height while the width kept going and the map would quietly stop being square. 80 rather than 100 leaves room for the page heading, the signed-in line, the map's own heading and the hint. The column carries the same cap so that when it bites, the column shrinks and flexbox hands the freed width to the list; capping only the map would leave the column holding its 3/5 of the row with a dead gap beside a smaller map.
  Side by side the list is capped at the **map column's** height and scrolls inside it, since a map with a few hundred imported places would otherwise leave the map stranded at the top of a long page. That cap is now exact rather than a shared constant: the row is `align-items: stretch`, the list column is itself a flex column, and `.hnsPoiArea` is `flex: 1 1 0` with **`min-height: 0`**. That one declaration is the whole mechanism — without it the list's own content sets the row's height and stretches the *map* column to match a few hundred rows, which is precisely backwards. (There used to be a `--mapHeight` custom property feeding both; it went when the map stopped having a height of its own to share.) The stacked order below 1200px is the original one, where the list runs down the page and the page scrolls.
- **A game map is the thing the game's data will hang off, and `/hideandseek/game-maps` is the only page that touches it.** `game_map` is `id` and `name`, nothing else — no owner (maps are shared between accounts) and no timestamps. Its unique index collates **NOCASE**, and `hnsGameMapNameError()` in `gameMap.php` collates the same way on purpose: if the check and the index disagreed about `Groningen` versus `groningen`, a clash would slip past the message and surface as a 500 from the insert. Which map is **loaded** is resolved in one place, `hnsLoadedGameMap()`, under one rule — **`?map=` wins and is written to the session; without it the session answers** — so the address stays linkable while the choice follows you between pages. Three things about that are deliberate: it looks the row up every time rather than trusting the session, so a map deleted in another tab stops being named instead of haunting every later join; the id lives *inside* the scoped session next to `account_id`, not in `modulePreference()` (which is for preferences that deliberately sit outside the scope), so `logIn()` replacing that array and `logOut()` dropping it both unload the map and no map ever follows a change of account; and `delete` does not clear the session itself, because the lookup already self-heals and two places doing it is one place to forget. The route follows `accounts.php` — POST, `checkCsrf`, dispatch on `action`, redirect — with one exception worth knowing: **a validation failure does not redirect**, because there is no flash mechanism here and a 302 would throw the message away.
- **POIs are imported from pasted Overpass output, onto the loaded game map, and the browser does the parsing.** `/hideandseek/import-pois` takes a category name and the raw data a player copied out of Overpass Turbo, in JSON or XML. `js/poiImport.js` parses it (`JSON.parse`, or `DOMParser` when the paste starts with `<`) and posts finished POIs — `{osmType, osmId, name, lat, lon}` — to `/hideandseek/ajax/import-pois`; the server never sees the paste. The request is a **list of categories** (`{mapId, categories: [{name, colour, icon, pois}]}`), an Overpass paste being a list of one, and the whole list is written in **one transaction** by `hnsImportCategories()`, so a batch with one bad category writes nothing. The category name is typed, never inferred from tags — a query for hospitals can match `amenity=hospital` or `healthcare=hospital` and the player's word for the set is neither. Positions come from `lat`/`lon`, else `center` (`out center`), else the middle of `bounds` (`out geom`); anything with none of those is counted as skipped and reported. **An untagged node that a way or relation in the same paste references is not a POI** — it is geometry from `>; out skel`, and importing it would scatter a POI along every outline.
  **The endpoint still validates every entry**, since anything can post to it: `hnsValidPoi()` in `poiImport.php` takes a known OSM type, a positive integer id (sent as a string — no JS precision question), coordinates sent as numbers and on the globe, and a name that is text or null. One bad entry refuses the whole request rather than saving the rest, because the only legitimate client never sends one. A category is unique per map under NOCASE, and a POI is unique per category by `(osm_type, osm_id)`, so a second paste into the same category merges and moves rather than duplicating. The request names its `mapId` rather than the endpoint reading the session, which keeps a map switched in another tab from receiving the import. On success the script navigates to the page with the counts in the query string — the skipped count only the browser knows — and a failure is reported in place, with the paste still in the box. Deleting a category stays an ordinary form post to the page route.
  **The Export button gives back the whole map in a format the same box reads.** `/hideandseek/ajax/export-pois` returns `hnsExportPois()`: `{format: "hideandseek-pois", version: 1, map, categories: [{name, colour, icon, pois}]}`, the POIs in exactly the shape the import endpoint takes, so `hnsParsePaste()` recognising `format` is all the import needed — it posts those categories straight through, and the Category, Colour and Icon fields are not used. `hnsFormatExport()` in `js/poiImport.js` writes it one POI per line rather than `JSON.stringify(…, null, 2)`, which would spend seven lines on each. A category with no colour or icon exports `""`, which the import reads as none. The text lands in a box under the button, selected, and is copied to the clipboard where the browser allows it; when it does not (a refused permission, or headless Chrome), the status says to copy it by hand. A test round-trips one map's export into a fresh map and checks the second export is identical.
  **A category has a colour and an icon** (`poi_category.colour`, `.icon`, both nullable). The colour is `#rrggbb`, stored lowercase; NULL falls back to `--imported`. The icon is **one grapheme**, checked with PCRE's `/^\X$/u` in `hnsPoiIcon()` — there is no mbstring or intl here, and `\X` is what makes a flag, a keycap, a skin-toned or a ZWJ emoji count as one character where a byte or code-point length would not; NULL means a plain dot. Both are set on import (re-importing into a category restyles it — the form pre-fills them when the typed name matches an existing category, from `data-colour`/`data-icon` on the datalist options) and edited in the category table on the import page, where the **name** is editable too. Every row's three fields belong to **one** form, `poiCategoriesForm`, through the `form` attribute (a field can belong to only one form, which is why there are no per-row forms any more), posted as `categories[id][name|colour|icon]` to action `styles`. A row's Save button submits that form with `only=<id>` and the server applies just that row; **Save all** submits it without `only`. Save all is the form's own button and sits *above* the table on purpose: Enter in a field submits through the form's first submit button in document order, and a row's Save coming first would quietly save one row. `hnsSaveCategoryEdits()` validates the whole request before writing anything — empty names, bad colours or icons, and **names checked as a set**: the names the map would end up with, ASCII-case-folded with `strtolower` to match the index's NOCASE, must all differ, so swapping two names in one save is legal. Writing a swap trips the unique index halfway, so renamed rows first take a placeholder of a space and their id (impossible as a real name, since names are trimmed) inside the same transaction. A refused save re-renders with what was typed (`categoryEdits`) rather than the stored values; ids that are not on the posted map are ignored. **An `<input type="color">` cannot be empty**: given no value it reads back as `#000000`, so `poiImport.js` fills every colour input whose `value` *attribute* is absent with `--imported` — reading `.value` instead would see the black and leave it.
- **Browser preferences are per module, not per site.** `$_SESSION['lang']` and `$_SESSION['hue']` each hold one entry *per module* (`$_SESSION['lang']['music']`, `$_SESSION['hue']['hideandseek']`, …), read and written only through `modulePreference()` / `rememberModulePreference()` / `forgetModulePreference()` in `app/util.php`. Never touch those keys directly: they were bare scalars until 2026-09-28, so a session written before then still holds a string where an array is expected — the helpers fall through to the default rather than reading an offset off a string, and writing through them repairs the shape. They live in `util.php` rather than `session.php` because `util.php` is loaded first and unconditionally, so no caller has to care which was required first.
- **One locale so far**, so `nav.php` renders the language menu only when `count(moduleLocales(...)) > 1`. Adding a locale is a line in `config.php` plus a `lang/<code>.php`; the route and the menu are already there.
- `ajax/whoami.php` exists only as a worked example of the guard's shape — copy it, then delete it.
